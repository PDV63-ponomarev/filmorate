### Filmorate 1.0

Первый спринт написания бэкенда для сервиса Filmorate - оценшик фильмов

### Модели данных
Создать пакет model, добавить в него два класса - Film и User. 
Это классы-модели данных приложения.

У model.Film должны быть следующие свойства:
- целочисленный идентификатор - id
- название - name
- описание - description
- дата релиза - releaseDate
- продолжительность фильма - duration

Свойства model.User:
- целочисленный идентификатор - id
- электронная почта - email
- логин пользователя - login
- имя для отображения - name
- дата рождения - birthday

Использовать аннотацию @Date библиотеки Lombok для упрашения создания сущностей

### Хранение данных
Данные можно хранить в памяти проложения, использовать контроллер.
В дальнейшем хранение переместиться

### REST-контроллеры
Создать два класса-контроллера. FilmController будет обслуживать фильмы,
UserController - пользователей.   
Проверить, что контроллеры соответствуют правилам REST  

Добавить в классы-контроллеры эндпоинты с подходищим типом запроса для каждого из случаев
Для FilmController: 
- добавление фильма
- обновление фильма
- получение всех фильмов

Для UserController:
- создание пользователя
- обновление пользователя
- получения списка всех пользователей

Эндпоинты для создания и обновления данных должны так же вернуть созданную или измененныую сущность.

Использовать аннотация @RequestBody, чтобы создать объект из тела запроса на добавление или обновление сущности.

### Валидация
проверить данные, которые приходят в запросе на добавление нового фильма или пользователя.
Критерии соответствия данных.  
Film:
- название не может быть пустым
- максимальная длина описания - 200 символов
- дата релиза не раньше 28 декабря 1895 года
- продолжительность должна быть положительной

User:
- электронная почта не может быть пустой и должна содержать @
- логин не может быть пустым и содержать пробелы
- имя для отображения может быть пустым, в таком случае используется логин
- дата рождения не можеть быть в будущем

Для обработки ошибки валидации нужно новое исключение, наприем - ValidationException

### Логирование
Добавить логирование для операций, которые изменяют сущность - добавляют и обновляют их.
Так же логирование причин ошибок - например, если валидация не пройдена.

Воспользоваться библиотекой slf4j для логирования и объявить логер для каждого класса,
так будет сразу видно где в коде выводится та или иная строка

    private final static Logger log = LoggerFactory.getLogger(Example.class);

Использовать аннотациюя @Slf4j библиотекие Lombok чтобы не создавать логер вручную

### Тестирование
Добавить тесты для валидации. Проверить работу на граничных условиях

Обратить внимание: Валидация не пропускает пустые или неверно заполненые поля.
Проверить как контроллер реагирует на пустой запрос

### Проверка
Так-как у API нет интерфеса, будет взаимодействие через веб-клиент. 
Использовать Postman для тестовых данных и теста API

### Дополнительное задание
Валидация основного задания - базовая. Возможны ошибки, например, с неправильным форматом почты

У Java есть инструмент для проверки корректности различных данных. С помощью аннотаций
можно задать ограничения, которые будут проверяться автоматически. Для этого добавиться в описание
сборки проекта следующиу зависимость

    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-validation</artifactId>
    </dependency>

Теперь можно применять аннотацию @NotNull к полю класса-модели для проверки на Null,
@NotBlank - для проверки на пустую строку, @Email - для проверки на соответствие формату электронного адреса

Чтобы Spring не только преобразорвывал тело запроса в соответствующий класс,
но и проверил корректность переданных данных, вместе с аннотацией @RequestBody нужно использовать аннотацию @Valid
    
    public createUser(@Valid @RequestBody User user)
