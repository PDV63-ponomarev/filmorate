### Filmorate 2
Улучшение Filmorate.
Добавление рейтинга фильмов и отзывов. Объединение пользователй в комьюнити.

Улучшение API приложения до соответствия REST, изменение архитектуры с помощью внедрения зависимостей.

Создать новую ветку, для запуска тестов в GitHub (add-friends-likes)

### Архитектура
Сейчас вся логика приложения в контроллерах. Нужно вынести хранение данных  
о фильмах и пользователях в отдельные классы. Назвать их "Хранилищами" (storage)

- Создать интерфейсы FilmStorage и UserStorage, в которых будут определены методы  
добавления, удаления и модификаций объектов.
- Создать классы InMemoryFilmStorage и InMemoryUserStorage, имплементироующие новый интерфейс,  
перенести туда всю логику хранения, обновления и поиска объектов.
- Добавить к InMemoryFilmStorage и InMemoryUserStorage антоацию @Component,  
чтобы впоследствии пользоваться внедрением зависимостей и передавать хранилище сервиса

Чтобы объединить хранилища, создать пакет storage. В нем будут только классы и интерфейсы,  
имеющие отношение к хранению данных, например storage.film.FilmStorage

### Новая логика
Добавить возможность пользователям добавлять друг друга в друзья и ставить фильмам лайки.
- Создать UserService, который будет отвечать за такие операции с пользователями,  
как добавление в друзья, удаление из друзей, вывод списка общих друзей. Пока пользователям  
не надо одобрять заявки в друзья, сразу добавляются. Если пользователь 1 стал другом пользователя 2,
то пользователь 2 друг пользователя 1.
- Создать FilmService, который отвечает за операции с фильмами - добавление и удаление лайка,  
вывод 10 наиболее популярных фильмов по кол-ву лайков. Пусть пока каждый пользователь может   
поставить лайк фильму только один раз.
- Добавить к ним аннотацию @Service - тогда к ним можно будет получить доступ из контроллера.

По аналогии с хранилищами, объединить бизнес-логику в пакет service.

Есть много способов хранить информацию о том, что два пользователя являются друзьями.  
Например можно создать свойство friends, в классе пользователя, которое будет содержать список его друзей.  
Можно использовать такое или иное решение. Для обеспечения уникальности значения (избежание добавление человека дважды),  
проще использовать для хранения Set<Long> c id друзей. Так же можно обеспечить условие   
"один пользователь - один лайк" для оценки фильмов.

### Зависимости  
Переделать код в контроллерах, сервисах и хранилищах под использование внедрения зависимостей
- Использовать аннотации @Service, @Component, @Autowired. Внедрить зависимости через конструктор классов
- Классы-сервисы должны иметь доступ к классам-хранилищам. Убедиться, что сервисы зависят от  
интерфейсов классов-хранилищ, а не их реализаций. Таким образом в будущем будет проще добавлять  
и использовать новые реализации с другим типом хранения данных.
- Сервисы должны быть внедрены в соответствующие контроллеры.

@Component - аннотация, которая определяет класс как управляемый Spring. Такой класс будет  
добавлен в контекст приложения при сканировании. 
@Service - не отличается по поведению, но обозначает более узкий спектр классов - такие,  
которые содержат в себе бизнес-логику и, как правило, не хранят состояние.
